Security

How HuhQueue protects your Buffer connection, your data and what your agents can do. The full threat model and audit are public.

Last updated 4 November 2026Applies to huhqueue-studio.onrender.com

In short

Encrypted tokensBuffer tokens are encrypted at rest and stay on the server.
Strict browser policyOur own scripts only, no framing, a CSRF header on every write.
Agents on a leashHashed scoped tokens, approval by default, caps and a kill switch.
Audited7 findings from the 31 Oct 2026 audit, all fixed with regression tests.

Signing in

  • Buffer OAuth 2.0 with PKCE; the session id is rotated at sign-in.
  • Session cookie: HttpOnly, Secure, SameSite=Lax. Every write also needs a CSRF token sent in a header.
  • Sign-in always opens as a full page in your browser, never inside a frame.

In your browser

  • Content Security Policy: scripts only from this site, no inline scripts, no third-party scripts or fonts, object-src 'none', frame-ancestors 'none'.
  • X-Frame-Options: DENY, X-Content-Type-Options: nosniff and a strict Referrer-Policy.

Your data

  • Buffer tokens and your own AI key are encrypted at rest and never sent to the browser.
  • Agent tokens, session ids, sign-in codes and device links are stored only as hashes.
  • Disconnect and delete removes your data at once.

AI apps and agents

  • Each token has a policy (approval, drafts only or trusted), a daily cap and an expiry, and can be revoked.
  • The kill switch and caps run before every agent action, over MCP and REST.
  • The MCP sign-in screen shows where it will send you back and flags unverified apps, which can't be given trusted access.

On the server

  • Every outbound fetch goes through one safe-fetch helper that re-checks each redirect against private, loopback and metadata addresses.
  • Request bodies are size-capped before parsing; anonymous and sample traffic is rate- and cost-limited.
  • Video workers authenticate with a GitHub OIDC identity and a single-use job token; no token appears in workflow logs.

Checks on every change

gitleaks on every push, pip-audit on dependencies, the full test suite on SQLite and Postgres, and a real-browser smoke test. The threat model, the audit's 7 findings, their fixes and known limits are in docs/SECURITY.md.

Report a vulnerability

Questions, a data request or a correction: open an issue on the project's GitHub, or message @huhbyte.ai on Instagram. For a security problem, use GitHub's private Report a vulnerability instead of a public issue.
